чтобы зарегестрировать карту необходимо авторизоваться либо логин\паролем админа рут, либо другой уже зарегестрированной персонализированной картой
Процедура авторизации состоит из # Процедура идентификации ранее зарегестрированной карты # (описана ниже) и сверки ролей пользователя из поля roles объекта cardIdentity
Исключение только для рут пользователя, для регистрации которого отправляем логин\пароль на сервер, далее в киклок и обратно успех операции.



При регистрации любых карт долен быть доступ к интернету/сети с сервером системы. Перед регистрацией это надо проверить.
При регистрации персонализированных карт андроид сканирует MIFARE DESFire EV1 карту с нулевым 3дес ключом (заводская
первоначальная установка). Карта должна пройти криптографическое рукопожатие с первоначальным нулевым ключом.
Если рукопожатие с нулевым ключом прошло без ошибок, то:
    берем новый ключ из таблицы 3дес ключей на андроиде (таблица предварительно самая последняя должна закачаться с 
    сервера), самый последний созданный по времени ключ, это можно сделать по UUID v7.
    (помним, что на стадии разработки и тестирования, у нас будет один единственный документированый ключ 3DES, который 
    может дублироваться в таблице 3DES ключей, так как процедура генерации ключей будет выдавать только один единственный)
    В зависимости от того, какую карту активируем, заполняем объект данными:
    
    cardIdentity:
    {
        "cardId":"UUID v7, генериться на андроиде, по ютс дате и времени",
        "uId":"7-байтный UID карты",
        "regionId":"",
        "organizerId":"",
        "carrierId":"",
        "cardsDistributorId":"",
        "auditServiceId":"",
        "userId":"",
        "roles":["роль пользователя карты"]
    }

    Выполняем процедуру # Процедура идентификации ранее зарегестрированной карты #, в случае успеха
        считываем объект cardIdentity, изменяем его согласно вновь введенным данным (не меняем cardId и uId), roles можно добавлять,

    В случае не успеха # Процедура идентификации ранее зарегестрированной карты # выдаем ошибку.



# Процедура идентификации ранее зарегестрированной карты #

Перебираем ключи из таблицы ключей 3des (на андроиде они шифрованные, и шифрованы АЕС ключом, который лежит защищенном кисторе анроида).
Ключи в таблице сортируем начиная с самого последнего по дате и времени по убыванию даты и времени (по UUID v7). Вначале пытаемся делать 
криптографическое рукопожатие с самым первым ключеом. Если прошло, то идентификация успешна.

Если не прошло, берем следующий ключ и проделываем с ним криптографическое рукопожатие, и так до тех пор пока не найдем 
подходящий ключ, либо ключи не закончатся (там они за последние 5 лет). Если ничего не нашли, выводим ошибку идентификации и прерываем всякие операции.
Если какой-то ключ сработал и прошел криптографическое рукопожатие, то перепрошиваем 0-й слот карты самым первым ключом в списке, делаем еще раз рукопожатие
с первым ключом в списке, и если все в порядке, то идентификация успешна.

# Часть I. Core Protocol v2.04 (JSON API)

Спецификация протокола взаимодействия с Сервером-агрегатором (предфронтом) и Транспортным приложением.

## 1. Формат сообщений

Все передаваемые сообщения содержат два блока данных:

| Блок данных | Назначение |
|---|---|
| Заголовок JSON сообщения | Выполняемая команда |
| Тело JSON сообщения | Содержательная часть сообщения в формате JSON |

- Запросы типов POST и GET. В теле запроса передаётся сообщение в формате JSON.
- `POST: URL-сервиса: ip:port/crim_card/{тип запроса}/`
- `GET: URL-сервиса: ip:port/crim_card/{тип справочника}/`

## 2. Поддерживаемые операции

| Операция | Команда |
|---|---|
| Создание, изменение, удаление связки документ(СНИЛС) — карта(хеш) | `crim_card/set_hash/` |
| Запрос льготы (для совершения поездки) | `crim_card/get_privilege/` |
| Уведомление Ядра об использовании поездки | `crim_card/set_info/` |
| Запрос льготы из личного кабинета | `crim_card/get_privilege_by_snils/` |
| Передача белых списков | `crim_card/whiteList/` |

## 3. Обязательность и типы полей

| Обозначение | Описание |
|---|---|
| M | Mandatory. Обязательное. Поле требуется в сообщении |
| O | Optional. Опциональное. Необязательное, но может быть включено отправителем |

| Обозначение | Тип |
|---|---|
| T | Text. Текстовое поле |
| N | Numeric. Цифровое поле |
| D | Date. Дата и время |

## 4. Составной код льготы

Используется для передачи сведений о льготах, доступных указанному СНИЛС. Состоит из цифр с разделителем дефис.

**Формат: `MSZ-TLK-TFL-FPL-TER`**. Пример: `10-750-10-03-10`.

| Поле | Название | Пример | Расшифровка значений |
|---|---|---|---|
| MSZ | Мера социальной защиты | 10 | 10 — «Льготный проезд в автобусах, троллейбусах по маршрутам регулярных перевозок в пригородном сообщении в пределах Республики Крым» (обязательна к заполнению, 0 — не допускается) |
| TLK | Тип льготной категории | 750 | 750 — «Участники Великой Отечественной войны» (обязательна к заполнению, 0 — не допускается) |
| TFL | Тип финансирования | 10 | 22 — Региональный бюджет; 10 — Республика Крым; 11 — Федеральный бюджет; 0 — не определен |
| FPL | Форма предоставления | 03 | 01 — Денежная; 02 — Натуральная; 03 — Льготы; 04 — Услуги; 0 — не определена |
| TER | Территория действия | 10 | 10 — Республика Крым; 92 — Севастополь; 0 — не определена. «Но скорее всего будет два: 82 или 10 — Крым / 92 — Севастополь» |

Расшифровка примера `10-750-10-03-10`: льготный проезд в автобусах, троллейбусах по маршрутам регулярных перевозок в пригородном сообщении в пределах Республики Крым (MSZ=10), участники ВОВ (TLK=750), финансирование — Республика Крым (TFL=10), форма — льгота (FPL=03), территория — Республика Крым (TER=10).

## 5. Таблица предоставления права на проезд по типу льготы

| № | Маршрут/МСЗ | 10 | 20 | 30 | 40 | 50 | 60 |
|---|---|---|---|---|---|---|---|
| 1 | Городской | — | — | — | — | А,Т,Тр | — |
| 2 | Пригородный | — | — | А,Т | — | — | Ж |
| 3 | Междугородный | А | А,Т | — | А,Т,Ж | — | — |

А — автобусы; Т — троллейбусы; Тр — трамваи; Ж — железнодорожный транспорт.

## 6. Справочник типов льгот (МСЗ)

| Код МСЗ | Наименование меры социальной защиты (поддержки) |
|---|---|
| 10 | Льготный проезд автобусами междугородных маршрутов в пределах Республики Крым |
| 20 | Льготный проезд в автобусах, троллейбусах междугороднего сообщения в пределах Республики Крым (МФК) |
| 30 | Льготный проезд в автобусах, троллейбусах по маршрутам регулярных перевозок в пригородном сообщении в пределах Республики Крым (МФК) |
| 40 | Льготный проезд в автобусах, троллейбусах, железнодорожным транспортом междугороднего сообщения в пределах Республики Крым (МФК) |
| 50 | Льготный проезд в автобусах, троллейбусах, трамваях, следующих по маршрутам регулярных перевозок в городском сообщении в пределах Республики Крым (МФК) |
| 60 | Льготный проезд железнодорожным транспортом общего пользования в пригородном сообщении в пределах Республики Крым (МФК) |

## 7. Взаимодействие с Сервером-агрегатором (предфронтом)

Информационные потоки:
- Request: Сервер-агрегатор → Шлюз Ядра
- Response: Шлюз Ядра → Сервер-агрегатор

### 7.1. Создание, изменение, удаление связки документ(СНИЛС) — карта(хеш)

`POST: ip:port/crim_card/set_hash/`

**Request:**

| Поле | Обяз. | Тип | Расположение | Комментарии |
|---|---|---|---|---|
| protocol.name | M | T | Заголовок | `core_card` |
| protocol.version | M | T | Заголовок | `1.0` |
| requestType | M | T | Заголовок | Тип запроса. `set_hash` — фиксированное значение |
| messageId | M | T | Заголовок | Guid сообщения |
| messageDateTime | M | D | Заголовок | Формат `YYYY-MM-DDTHH:MM:SS` |
| action_type | M | T | Тело | Тип действия: `add` — добавить, `remove` — удалить, `change` — изменить |
| dateAction | M | D | Тело | Дата и время транзакции |
| docCode | M | T | Тело | Наименование процедуры работы с данными (`SNILS`) |
| snilsNumber | M | T | Тело | СНИЛС. Допустимые символы 0–9 |
| hpan | M | T | Тело | HEX номера карты |
| mask | O | T | Тело | Последние 4 цифры номера карты |

**Response:** `protocol.name`, `protocol.version` (M, T, заголовок), `messageId` (M, T, заголовок), `messageDateTime` (M, D, заголовок), `response.type` (M, T), `response.code` (M, T), `response.message` (M, T) — в теле.

**Коды ответов (специфичные для set_hash):**

| Type | Code | Message | Комментарии |
|---|---|---|---|
| SUCCESS | 0001 | Successfully completed. | Успешно |
| ERROR | 0002 | Object not found. | При `change`/`remove` — СНИЛС не найден |
| ERROR | 0003 | The object already exists. | При `add` — СНИЛС уже существует |
| ERROR | 0004 | Invalid request type. | Не удалось определить тип запроса |
| ERROR | 0005 | Invalid format. | Сообщение не соответствует формату обмена |
| ERROR | 0006 | Invalid DB | Запрос валидный, но его не удалось передать в базу данных |
| ERROR | 0007 | Program error | Непредвиденная ошибка |
| ERROR | 0008 | Error URL/requestType | URL не соответствует типу запроса |

**Пример запроса:**

```json
{
  "header": {
    "protocol": { "name": "core_card", "version": "1.0" },
    "messageId": "2ca7f8f0-5c92-4619-b2f5-592ca",
    "messageDateTime": "2018-10-16T14:53:55",
    "requestType": "set_hash"
  },
  "body": {
    "actionType": "add",
    "dateAction": "2018-10-16T13:52:55",
    "docCode": "SNILS",
    "snilsNumber": "46343638496",
    "hpan": "AC117CC01475C6736E393DA8A1EF1E01D61E953EB4FC",
    "mask": "2125"
  }
}
```

**Пример успешного ответа:**

```json
{
  "header": {
    "protocol": { "name": "core_card", "version": "1.0" },
    "messageId": "2ca7f8f0-5c92-4619-b2f5-592ca",
    "messageDateTime": "2018-10-16T14:53:57"
  },
  "body": {
    "response": {
      "type": "SUCCESS",
      "code": "0001",
      "message": "Successfully completed"
    }
  }
}
```

## 8. Взаимодействие с Транспортным приложением

### 8.1. Запрос льготы для совершения поездки

Льгота передаётся в транспортное приложение по факту осуществления проезда на дату и время фактического прохода пассажира (прикладывания карты к валидатору). Дата и время фактического применения льготы (проезда) передаётся транспортным приложением по факту осуществления связи с предхостом АСОПК и соответствует дате и времени совершённой транзакции. Дата и время осуществления транзакции указана в запросе льгот для совершения поездки.

`POST: ip:port/crim_card/get_privilege/`

**Request:**

| Поле | Обяз. | Тип | Расположение | Комментарии |
|---|---|---|---|---|
| protocol.name | M | T | Заголовок | `core_card` |
| protocol.version | M | T | Заголовок | `1.0` |
| requestType | M | T | Заголовок | `get_privilege` |
| messageId | M | T | Заголовок | Guid сообщения |
| messageDateTime | M | D | Заголовок | `YYYY-MM-DDTHH:MM:SS` |
| transactionDate | M | D | Тело | Дата и время транзакции, `YYYY-MM-DDTHH:MM:SS` |
| hpan | M | T | Тело | HEX номера карты |
| rideId | M | T | Тело | Id поездки |

**Response:** заголовок (те же поля + `requestType`), в теле:

| Поле | Обяз. | Тип | Комментарии |
|---|---|---|---|
| response.type / response.code / response.message | M | T | Тип/код/сообщение ответа |
| response.snilsNumber | M | T | СНИЛС |
| response.isPrivileged | O | T | Льготник — `Y`, сопровождающий — `N` |
| privilegeCategory[].code | M | T | Составной код льготы |
| privilegeCategory[].guid | M | T | GUID льготы |
| privilegeCategory[].dateBegin | M | D | Дата начала действия, `YYYY-MM-DD` |
| privilegeCategory[].dateEnd | M | D | Дата окончания действия, `YYYY-MM-DD` |
| privilegeCategory[].privilegePercent | O | T | Скидка в процентах, 0–9 |
| privilegeCategory[].privilegeCount | O | T | Количество, 0–9 |
| privilegeCategory[].privilegeSumm | O | T | Сумма, 0–9, разделитель «.» |
| privilegeCategory[].accompanyPerson | M | T | `N` — не является сопровождающим, `Y` — является сопровождающим* |
| privilegeCategory[].accompanyDocNum | M | T | СНИЛС* |

\* Правила заполнения полей сопровождающего:

1. `"accompanyPerson": "N"`, `"accompanyDocNum": null` — льгота, у которой нет сопровождающего.
2. `"acpanyPerson": "Y"`, `"accompanyDocNum": "222333666512"` — льгота сопровождающего, у которой назначен сопровождаемый. `accompanyDocNum` — СНИЛС-основание, т.е. СНИЛС сопровождаемого.
3. `"accompanyPerson": "N"`, `"accompanyDocNum": "222333666512"` — льгота сопровождаемого, у которой назначен сопровождающий. `accompanyDocNum` — СНИЛС-основание, т.е. СНИЛС сопровождающего.

Данные поля не отвечают за предоставление льготной поездки. Эта информация необходима для формирования отчётов.

**Коды ответов (специфичные для get_privilege):**

| Type | Code | Message | Комментарии |
|---|---|---|---|
| SUCCESS | 0001 | Successfully completed. | Успешно |
| ERROR | 0002 | Object not found. | Хеш не найден / нет льготы |
| ERROR | 0005 | Invalid format. | Сообщение не соответствует формату обмена |
| ERROR | 0006 | Invalid DB | Запрос валидный, но его не удалось передать в БД |
| ERROR | 0007 | Program error | Непредвиденная ошибка |
| ERROR | 0008 | Error URL/requestType | URL не соответствует типу запроса |

### 8.2. Уведомление Ядра об использовании поездки

`POST: ip:port/crim_card/set_info/`

**Advice (Request):**

| Поле | Обяз. | Тип | Расположение | Комментарии |
|---|---|---|---|---|
| protocol.name | M | T | Заголовок | `core_card` |
| protocol.version | N | T | Заголовок | `1.0` (в таблице источника — N) |
| requestType | M | T | Заголовок | `set_info` |
| messageId | M | T | Заголовок | Guid сообщения |
| messageDateTime | M | D | Заголовок | `YYYY-MM-DDTHH:MM:SS` |
| response.type | M | T | Тело | Тип ответа |
| response.code | M | T | Тело | Код ответа |
| response.message | M | T | Тело | Сообщение |
| privilege_used.ride_id | M | T | Тело | ID поездки |
| privilege_used.ride_amount | O | T | Тело | Сумма поездки. Символы 0–9, разделитель «.» |
| privilege_used.rideCode | M | T | Тело | Составной код льготы |
| privilege_used.guid | M | T | Тело | GUID льготы |

**Коды ответов (специфичные для set_info):**

### 8.3. Передача белых списков

Передача выполняется POST-запросом **на сервер транспортного приложения**. Запрос содержит информацию о хешах и связанных льготах, актуальных или новых на момент передачи. Первый раз процедура передаёт все записи с активными льготами, в последующем — накопительным итогом. Периодичность — 1 раз в 15 минут.

`POST: ip:port/crim_card/whiteList/`

**Порядок обновления информации.** Загрузка записи на первоначальном этапе осуществляется при определении связки льгота–хеш, в последующем — по факту обновления данной связки.

Первоначально событием для подготовки к загрузке может быть:

- льгота присутствует в ядре, получен запрос на привязку карты (хеша) к льготе;
- карта (хеш) присутствует в ядре, получена льгота от Центра выплаты;
- записи по льготам, привязанные в ядре как новые с датой окончания менее текущей даты, в состав белых списков **не направляются**. Если впоследствии при обновлении информации по льготам была получена дата окончания, равная или более текущей даты, такая запись будет направлена в составе белых списков;
- записи по льготам, привязанные в ядре как новые с датой начала более/менее текущей даты, направляются в белые списки в соответствии с обычной очередностью.

Все новые связки определяются по СНИЛС, обновление связки — по СНИЛС и составному коду льготы.

Последующие события — обновление информации:

- у льготы обновилась карта (хеш hpan);
- у льготы обновилась дата начала/окончания срока действия (dateStart/dateStop);
- у льготы обновился GUID;
- появилась/исчезла возможность проезда с сопровождающим (personsAllowed).

Уникальность связки определяется параметрами СНИЛС–составной код льготы (snils–benefitCode). Любая запись с новой уникальной связкой, у которой заполнено поле хеш (hpan), будет выгружена в белые списки как новая запись. Для связок, выгруженных ранее, при обновлении даты окончания действия льготы и значения поля GUID будет выгружена запись также в полном объёме, в состав которой войдут изменённые поля.

**Advice (Request):**

| Поле | Обяз. | Тип | Комментарии |

## Общие правила

- Формат обмена — **CSV**.
- Разделитель полей — символ **`;`**.
- Для файлов Services/R-Services явно указано: разделитель — «;», кодировка **UTF-8**.
- `[реконструкция]` Каждая строка файла — одна запись; первая строка — заголовок с наименованиями колонок (фрагмент источника: «…строка – … (…), …строки, …» `[утрачено]`).

**Именование файлов:** `{ПРЕФИКС}-YYYYMMDD-NNN-VV.csv`

| Часть | Значение |
|---|---|
| ПРЕФИКС | Тип файла (SNILS / R-SNILS / MSZ / TLK / Services / R-Services) |
| YYYYMMDD | Дата формирования файла (YYYY — год, MM — месяц, DD — день) |
| NNN | Порядковый номер файла за день |
| VV | Версия файла. Начинается с 01 `[реконструкция: при повторной отправке файла версия увеличивается]` |

- Файл назначений льгот передаётся оператором в Ядро; квитанция (`R-…`) возвращается обратно.
- Справочники передаются полностью при каждом обновлении; даты начала/окончания определяют актуальность записей `[реконструкция]`.

| 8 | `[реконструкция: форма предоставления (FPL)]` | Значения с дефисом: 01-, 02-, 03-, 04- (ср. FPL части I: 01 Денежная, 02 Натуральная, 03 Льготы, 04 Услуги) |
| 9 | Битовая маска маршрутов `[реконструкция]` | Фрагмент: «… 1000 – … …; 0100 – … …; 0110 – … …» (вероятно, виды сообщения: межгор./пригор./городское; ср. таблицу п. 5 части I) |
| 10 | Территория `[реконструкция]` | В примере: `91` (код региона Республика Крым; 92 — Севастополь) |

**Пример** (дословно; наименование утрачено):

```csv
1;2018-09-07;0760;<наименование утрачено>;2016-10-14;2017-01-01;03;0010;91;
```

## 5. Файл фактов поездок `Services-YYYYMMDD-NNN-VV.csv`

Назначение: передача фактов поездок (валидаций) по мере осуществления `[реконструкция]`. Разделитель — «;», кодировка UTF-8.

Доменные сущности спецификаций сопоставляются с платформой ASOP:

| Сущность «Базис»/Минтруд | ASOP |

| Белые списки (hpan → льгота, офлайн-валидация) | дельта-синхронизация справочников на терминал |
| get_privilege (онлайн-проверка по hpan) | потенциальный интеграционный шлюз gateway → Ядро |
